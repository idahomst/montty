# Code review, November 2026: findings and plan

A whole-repo review (about 30k lines of Rust plus docs, scripts and CI). It was done on macOS, where montty does not
build yet, so nothing below has been compiled or tested. Items marked **(verified)** were checked by hand. The rest
came from reading the code, so confirm each one (grep for callers, read the code) before changing anything. Line numbers
are approximate (`~`) and refer to commit `db65825`.

The verdict overall: the code is in good shape. There is no TODO/FIXME and no `#[allow(dead_code)]`, and the docs match the code
(every option and action is documented). The findings are mostly duplication, one-line wrappers that exist only for
tests, and some stale comments, plus two real problems in the responsiveness paths.

**Status:** steps 1 to 3 are done on Linux (branch `review-2026-11`; skipped items say why in their commit messages).
Still open: step 4 (on the Mac), the X11 paste check against a hung clipboard owner, and re-measuring
`scripts/bench.sh` in Xephyr for steps 1 and 3.

## How to work through this

Do it as four steps, one commit each (or a few small commits per step). Follow AGENTS.md:

- After every step: `cargo fmt --check`, `cargo clippy --all-targets` (warning-free), `cargo test`.
- Steps 1 and 3 touch hot paths (PTY wakeup, mouse move, draw). Re-measure with `scripts/bench.sh` (in Xephyr, not on
  the live display) and update `docs/bench.md` if the numbers move.
- When you inline a wrapper that exists only for a test, drop that test too. Keep tests that pin a real rule.
- Skip any item that turns out to be wrong or not worth it, and say why in the commit message.
- Delete this file when the work is done (step 2 or later).

## Step 1: bugs and responsiveness

1. **X11 paste blocks the UI thread** **(verified)**. `src/clipboard.rs:~200` (`system_clipboards`): only the Wayland
   path is wrapped in `Threaded::spawn(.., LOAD_TIMEOUT)`. The X11 `System` is returned bare, so a paste from a hung
   selection owner freezes the UI for copypasta's own (longer) timeout. Fix: wrap the X11 `System` in `Threaded` too.
   Check that `Drop` and ordering still hold for X11.
2. **The PTY-output hot path allocates** **(verified)**. `tabs::visible` (`src/window/tabs.rs:~161`) runs on every
   `Event::Wakeup` (`src/window/mod.rs:~987`) and calls `tree.panes()`, which builds a `Vec` (`src/layout/tree.rs:~510`).
   `Tabs::tab_of` does the same for every tab. Add a non-allocating `SplitTree::contains(PaneId)` and use it in
   `visible`, `tab_of`, `tab_marks` and `tab_dot_label`.
3. **The top bar is rebuilt on every pointer move**. `marks.rs` `dot_under_pointer` calls `self.bar()` (which runs
   `tab_labels`, a `String` per tab, `tab_marks` and the full layout) before it checks `y < bar.height`. Check the
   height via `bar_metrics()` first. Also, `draw_bar` calls `self.bar()` and then `tab_marks()` again; compute it once.
4. **Fallback glyph scan on the UI thread**. `src/font/mod.rs:~349` `scan_db`: a miss scans every system face
   (`with_face_data` + `FontRef::from_index`). The first frame that shows an uncovered char (CJK, a symbol) can stall for
   tens of ms; misses are cached per char only. Options: cache per-face coverage lazily, or skip faces already tried.
   The same function has an unreachable guard (`emoji && !is_emoji_face && best >= 100`) to delete.
5. **Per-frame lookups in `redraw`**. `src/window/draw.rs:~62-77`: `pane_profile(id)` / `pane_font(id)` do a store
   lookup and an `Arc` clone up to 3 times per pane per frame. Fetch them once per pane.
6. Small ones:
   - `ui/toast.rs:~95` `Toast::rect`: `y` goes negative when the window is shorter than the toast. Add `.max(0)` like
     the other modals, plus a test.
   - `config/profile.rs` `with_name`: `in_table |= t.starts_with('[')` also fires on a continuation line of a
     multi-line array, so a top-level `name` after such an array is skipped and a rename appends a second `name =`.
     Add a test with a multi-line array before `name`, then fix.

Optional, measure first: `render/atlas.rs:~100` hashes every visible cell with SipHash each frame (an FxHash-style
`BuildHasher` or an ASCII fast path would help). `render/cells.rs:~86` pushes instances for blank cells that draw
nothing when the background is translucent. `render/image.rs:~283` clones the whole image just to premultiply it.

## Step 4: macOS port groundwork (do on the Mac)

`cargo build` fails on macOS today: `notify` is built with `default-features = false`, so it has no macOS backend
(enable `macos_fsevent` or `macos_kqueue` for macOS only). Then put the Linux-specific code behind a `platform` module
with per-OS implementations:

| Where | Linux today | macOS needs |
|---|---|---|
| `clipboard.rs` | copypasta X11/Wayland, PRIMARY | NSPasteboard (`copypasta::ClipboardContext`), no PRIMARY |
| `device_events.rs` | x11-dl XInput2 | no-op |
| `window_menu.rs` | `_GTK_SHOW_WINDOW_MENU`, Wayland | no-op |
| `notify.rs` | `notify-send` | `osascript` or UserNotifications |
| `term/pane.rs` | `/proc/<pid>/cwd`, `WINDOWID` | `proc_pidinfo` (`PROC_PIDVNODEPATHINFO`), no WINDOWID |
| `font/mod.rs` | `fc-match monospace`, DejaVu/Noto/Liberation, "Noto Color Emoji", 96/72 DPI | Menlo/SF Mono, Apple Color Emoji (sbix), check the DPI factor |
| `decoder.rs` | `RLIMIT_AS` guard on the child | not enforced on macOS; needs another guard |
| `window/gl.rs` | GLX/EGL | CGL via glutin; ask for a 3.3 core profile |
| `Cargo.toml` | x11/wayland features on winit, glutin, copypasta | target-specific dependency tables |

Pure modules (`osc_scan`, `snapshot`, `links`, `status`, `colors`, `grid_point`, `pty_tap`) are portable as they are.
